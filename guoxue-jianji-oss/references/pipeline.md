# 文案 / 剧本 / spec 写法详解

## 一、从素材到口播稿

### 读图
- 用读图工具逐字提取：**干支、书名、作者、日期、标签、正文定义与案例、按钮文字**。
- 只写图上实际可见的内容，不补全、不推断。读不清就标注「读不清」。
- 多个来源冲突时，列出冲突并提醒用户核对，不要自行取舍（例如排盘 App 的时柱「丙辰」与书页案例的「己未」）。

### 口播稿结构（约 300–420 字）
1. **钩子**：一句反常识的切入（例：「一张 1908 年的老命盘，凭什么被写进命理教材？」）。
2. **出处**：书名 + 作者 + 这页在讲什么。
3. **主体**：2–3 个知识点，每个 2–3 句，用「术语 + 古籍说法 + 白话解释」三段式。
4. **收束**：把符号结构翻译成一句现代话（例：「不是算准了什么，是把人怎么调动资源画成了一张图。」）。
5. **行动**：评论区互动（例：「想看更多这种老断例，评论区告诉我。」）。

### 合规红线（写文案阶段就要规避）
- 不出现：算命、预测、改运、加微信、付费咨询、灵验、招财。
- 不对真实人物（含用户本人）做推断；用古籍案例与历史人物。
- 片尾固定免责声明，见 `compliance.md`。

## 二、双人对话剧本（12 段左右）

| 段 | 角色 | 作用 | 镜头 |
| --- | --- | --- | --- |
| 1 | 命主 | 递上材料、提问 | TWO / T2V |
| 2 | 老先生 | 不给吉凶，引出书上的词 | MASTER / M |
| 3 | 老先生 | 摆事实（可带静态排盘卡） | MASTER / M |
| 4 | 命主 | 短促追问 | VISITOR / V |
| 5 | 老先生 | 知识点 A | MASTER / M |
| 6 | 老先生 | 知识点 B | MASTER / M |
| 7 | 老先生 | 归纳 | MASTER / M |
| 8 | 命主 | 再追问 | VISITOR / V |
| 9 | 老先生 | 知识点 C + D | MASTER / M |
| 10 | 老先生 | 收束 | MASTER / M |
| 11 | 命主 | 感叹（接话） | TWO / T2V |
| 12 | 老先生 | 落点金句 | TWO / T2M |

**硬规则**：一个知识点 = 一句台词。台词里必须出现该知识点的**术语原词**（spec 的 `at` 字段靠它定位时间）。台词被拆成两段时，第二段用 `at_sec: 0` 承接已出现过的行。

## 三、spec JSON 字段

```jsonc
{
  "output": "/abs/path/out.mp4",          // 必填（或用 --out 覆盖）
  "end_card": {
    "gold_lines":   ["古籍最有意思的", "不是「算准了什么」"],  // 64px 金色
    "cream_lines":  ["是把才华怎么沉淀成体系", "画成了一张图"],// 42px 米白
    "cta":          "想看更多老断例，评论区告诉我",
    "disclaimer":   ["本视频为古籍文本情景演绎，仅作传统文化讨论",
                     "不构成任何人生预测或建议"]
  },
  "segments": [ /* 见下 */ ]
}
```

### segments[]
| 字段 | 说明 |
| --- | --- |
| `role` | `老先生` / `命主`，决定音色与语速 |
| `text` | 台词；知识点术语必须出现在其中 |
| `shot` | `MASTER`（老先生单人）/ `VISITOR`（命主单人）/ `TWO`（双人同框） |
| `box` | 人脸框键，与 shot 配套：`M` / `V` / `T2M`（双人里的老先生）/ `T2V`（双人里的命主） |
| `rate` | 可选，覆盖默认语速（老先生 `-8%`、命主 `+2%`） |
| `popup` | 可选，见下 |

### popup
| 字段 | 说明 |
| --- | --- |
| `mode` | 省略 = 灵动思考弹窗；`"static"` = 整图卡片只做淡入 |
| `title` / `sub` / `tag` | 弹窗标题 / 副标题 / 右上角标签（如「古籍断例 ②」） |
| `rows[]` | 知识点行，按顺序逐条弹出 |
| `y` | 弹窗顶边 y（默认 176；脚本会自动上移，保证底边不越过 655） |
| `image` + `width` + `y` + `at` | 仅 `mode: "static"`：整图卡片路径（相对 `assets/` 或绝对路径）、宽度、位置、淡入时刻 |

### popup.rows[]
| 字段 | 说明 |
| --- | --- |
| `no` | 编号徽章文字，如 `①` `②` `◆` |
| `term` | 术语（38px，强调色） |
| `detail` | 说明（25px 灰） |
| `result` | 结论 chip（如「名 / 位置」） |
| `color` | `gold` / `teal` |
| `at` | **台词中出现的关键词**，脚本按加权字符位置估算弹出时刻（误差 <0.3s） |
| `at_sec` | 直接指定秒数；已说过的知识点写 `0` |

## 四、弹窗版式规则

- 弹窗宽 872（静态图片模式用 `width` 单独指定），圆角 34。
- 内容区结构：左上跳动三点 → 标题 42px → 右上标签 → 副标题 25px → 渐隐分隔线 → 知识点行（行高 100）。
- 行内：编号徽章 58×58 → 术语 38px → 说明 25px → 右侧结论 chip。
- **底边不越过 y=655**（MASTER 头顶约 y=690），超出的双行弹窗会被自动上移。
- 静态卡片：宽度 760、y=130（底边约 665），只做 0.35s 淡入。

## 五、跑与验

```bash
# 单段试做（调试弹窗节奏用）
python3 scripts/compose_episode.py spec.json --only 5 --out /tmp/t.mp4

# 整集
python3 scripts/compose_episode.py spec.json --out /abs/path/out.mp4
```

核验清单：
1. 抽 4–8 帧：弹窗未遮脸、字幕完整、术语行在正确时刻出现。
2. `ffmpeg -i out.mp4 -af volumedetect -f null -` → mean 约 −28dB、max 约 −7dB。
3. 时长 ≈ 台词总时长 + 3.5s 尾板；分辨率先对 1080×1920。
4. 相邻两帧对比，确认人物在动、嘴型在跟。
